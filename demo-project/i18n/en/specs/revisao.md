# Task `revisao` — security and quality review (final gate)

You are the last step of the swarm. A security game with security flaws would be the worst possible example. You do not fix code: you give a verdict with concrete problems.

## What you read, and only this

1. `.workshop/revisao-resumo.md`, generated by `tools/review-digest.mjs`. It contains three things:
   - the task table;
   - the static checks (CSP in the server and dangerous patterns found in `cards/`, `public/`, `pages/`, `templates/` and `lib/`);
   - the list "Files to review closely".
2. The files on that list, and no others. If the digest points to a dangerous pattern in a file that is not on the list (a `card.js`, for example), read that one too.

Do not explore the rest of the project. The budget is tight.

## Checklist

### `server.js`
- Binds only to `127.0.0.1`.
- Every response carries the CSP without `'unsafe-inline'` or `'unsafe-eval'`, including error, JSON and SSE responses. The expected CSP has `default-src 'self'`, `script-src 'self'`, `style-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'` and `require-trusted-types-for 'script'`.
- It also sends `X-Content-Type-Options: nosniff`, `Referrer-Policy` and `Cross-Origin-Opener-Policy`.
- **Path traversal:**
  - the path is decoded before it is validated;
  - it refuses segments that start with `.` (catches `..`, `.workshop`, `.claude`, `.git`), `\`, NUL and `:`;
  - it resolves inside the allowed folder and confirms with `realpath`, because of symbolic links;
  - it serves only the listed folders (`public/`, `cards/`, `templates/`, `lib/`, `pages/`, `replays/`) and only known extensions;
  - `server.js`, `package.json` and `plan.json` are never served.
- `/api/replay/<nome>` validates the name with a regular expression before touching the disk.
- No `eval`, no `child_process`, no reading of `.env`. An error does not send the stack trace to the browser.

### `public/app.js` (and the modules it imports from `public/`, if they are on the list)
- **Data in the DOM:** only through `textContent`, `createTextNode`, `el()` or `h()`. Never `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `srcdoc` or `on…=`.
- Ids that come from the hash (`#/cartao/<id>`) are validated before they go into an `import()` or a URL. `href`s are internal only.
- `localStorage` and `sessionStorage` are inside `try/catch` and store nothing sensitive.
- No `eval`, `Function` or `setTimeout` with a string.

### `pages/categoria.js` and `pages/pontuacao.js`
- They use only `h()` from `../templates/common.js`, never `document` or `window`, and no HTML built from text.
- The numbers match the spec: points = `difficulty × 10` and only `certo === true` counts.

### `lib/hash.js`
- It is a pure module: no network, no `node:crypto`, no `crypto.subtle` and no global state.

### The cards' `validate()`
Review it only in the cards the digest points to, or in those with a red test.
- It accepts only the right answer and compares strictly (`===` or `normalizar()`).
- It rejects `''`, `undefined` and wrong types.
- It never throws.

### Secrets, in every file you read
Look for keys and tokens in the code: `sk-ant-`, `ghp_`, `AKIA`, `-----BEGIN` and `password =` with a literal value.

## Severity

The values of `gravidade` stay as they are (`alta` = high, `media` = medium, `baixa` = low): the orchestrator reads them.

| `gravidade` | When |
|---|---|
| `alta` | Exploitable: XSS, path traversal, missing CSP or CSP with `unsafe-*`, server open beyond 127.0.0.1, a secret in the code. |
| `media` | A missing defense but no direct exploit; a `validate()` that accepts wrong answers; a task that failed for good (one problem per task, up to 3). |
| `baixa` | Quality: text that is not plain English, dead code, confusing names. |

## Verdict

The values of `veredito` also stay as they are:

- `reprovado` (rejected): there is at least one `alta` problem.
- `aprovado_com_reservas` (approved with reservations): there are problems, but none is `alta`.
- `aprovado` (approved): there are no problems.

## Result: `.workshop/veredito.json`

Valid JSON, no comments, with exactly these fields:

```json
{
  "veredito": "aprovado_com_reservas",
  "resumo": "The server and the app pass the critical points: strict CSP, refused paths and DOM only through textContent. One reservation remains: card re-01 failed for good and is not in the game.",
  "problemas": [
    {
      "gravidade": "media",
      "ficheiro": "cards/re-01/card.js",
      "descricao": "The task failed for good: validate() accepts the wrong order [\"syn\",\"ack\",\"syn-ack\"].",
      "correcao": "Compare the received list with the right order element by element, as in templates/ordenar.js."
    }
  ]
}
```

- **`resumo`:** two sentences.
- **`problemas`:** at most 8, from most to least serious. Each `descricao` has up to 200 characters and says where the problem is (function or line). Each `correcao` says what to change and where. With no problems, `problemas` is `[]`.
- Text in plain English.
- Do not change any other file.

At the end, reply with ONE single line: `OK revisao: <veredito>`.
